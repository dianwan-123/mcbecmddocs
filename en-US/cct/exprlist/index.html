Notes by senxyzplayeE#

a: A very large positive number, which mathematically should ideally be positive infinity. However, due to game precision limits, in the command community, command players typically choose values like a = 512, 1024, or 2048.

b: A positive number very close to 0, which mathematically should ideally be infinitesimal. However, due to game precision limits, in the command community, command players typically choose values like b = 0.01 or 0.001.

n: Compared to the HTML-like large numbers a and b mentioned above, this is a normal-scale number (command players typically choose 1, 2, or 3). It is a variable of engineering significance. In practice, adjusting n allows you to tune the adaptation interval.

For example, the "Division Formula (2D Vector)" cannot be used in the Java Edition directly, but after adjusting n, it becomes usable in the Java Edition.

n only becomes meaningful when considering floating-point errors. The value of n must be determined based on the specific scenario.

[★] Note: If the transformation formula already contains n, please ignore the explanations regarding n (except for this [★] note). For example, for the transformation (x, y, z) \to (x/n, y/n, z/n), directly ignore the explanations about n (except for this [★] note). Also, note that n is a real number.

{A+y}: A player's rotation can essentially be viewed as a unit vector. Let vector y = (0, 1, 0). Then, A + y yields a new vector m. {A+y} represents the direction of this vector m. For example, rotated as {A+y} means: rotating towards the direction of the new vector obtained by adding the look vector of entity A to vector y.

〈rx, ry〉: This refers to the rx (pitch) and ry (yaw) rotations in the game. For ease of understanding, take the following subcommand as an example: rotated 55 30. This would be written as 〈30, 55〉.

The transformation 〈rx, ry〉 → 〈0, x〉 means: the pitch rx becomes 0, and the yaw ry becomes x in radians (i.e., x radians). This is a somewhat ambiguous notation, so please read it carefully.

Bold Capital A: Represents an entity, e.g., rotated as A.

<>: Placeholders for a coordinate or an entity. For example, in facing <>, you can replace <> with (0, 0, 0) or other coordinates. Using (0, 0, 0) as an example yields facing 0 0 0. If you want to target an entity, you must complete the syntax yourself. For example, if <> is replaced with @e[name=a], it becomes facing entity @e[name=a] feet.

{A}, {B}: Placeholders for an entity. The author omitted the full syntax for brevity, so readers must complete it themselves. For example, the author writes facing {A}; if you want to target the entity @e[name=a], you should rewrite it as facing entity @e[name=a] feet.

Non-bold Capital A: Same as the explanation for "a" above, representing a large number.

r in the mathematical transformation table: Here, r = \sqrt{x^2 + z^2}, similar to the radial coordinate r in cylindrical coordinates.

?: In the transformations implemented by the formulas, you might see that some of the resulting formulas contain a "?". The author did not calculate these because resolving these "?" expressions would make the transformation table overly complex without offering much practical utility.

<ry+90, 0, xz>: Suppose the execution position of the entity before applying the formula is (x, y, z) (denoted as point M), and its rotation is (ry, rx). After applying the formula, the entity's rotation changes to (ry+90, 0), and its distance from point M becomes x \cdot z.

Uncertainty (不确定度): The author initially intended to roughly estimate the floating-point error, where \varepsilon represents the minimum precision when the angle approaches 0°. It was later discovered in practice that "uncertainty" is not the dominant cause of "floating-point error." Consequently, later formulas omit this "uncertainty" field. Currently, no one other than the author knows the algorithm used to calculate this uncertainty.
