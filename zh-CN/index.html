指令入门教程

注：本文章由Claude Fable 5结合wiki.bedrock.dev及minecraft wiki写成

前言：用指令搭建你的专属游戏世界#

在《我的世界》（Minecraft 基岩版）中，指令就像是一门专门用来和游戏引擎对话的魔法语言。无论你是想给自己的生存存档做个自动商店、做一张好玩的解密/冒险地图，还是想搞清楚服务器里各种神奇功能的底层逻辑，指令都是绕不开的强大工具。

很多人觉得指令难学，是因为网上的教程要么只给一串看不懂的代码，要么充斥着复杂的术语。本书将用最通俗易懂的语言、结合实际案例，带你一步一个脚印地从零开始，搞懂命令方块、玩转全新 /execute、搭建记分板系统，直到学会二分法和神奇的 nx树（MEF / execute fork） 黑科技。

第 1 章 认识指令方块——把手动指令变成全自动机器#

告别手动敲指令的时代#

平时我们在聊天框里打 /gamemode c 或者 /time set day，只能一次性执行一条命令。如果在做地图时，需要每时每刻检测玩家的位置、或者玩家踩到某个地方就自动触发剧情，手动输入就无能为力了。这时，我们需要一个能帮我们“自动打字执行”的工具——命令方块（Command Block）。

命令方块的三种颜色与核心设置#

命令方块在创造模式物品栏里是找不到的，需要输入指令获取：

放置并右键打开它，你会看到几个关键选项：

1. 三种方块形态（看颜色认功能）#

  • 脉冲（Impulse，橙色）：给它一次红石信号（比如按一下按钮），它就执行一次。
  • 连锁（Chain，绿色）：它自己不会主动触发，必须紧挨在别的命令方块后面；前面的方块执行完了，它顺着箭头立即跟着执行。
  • 循环（Repeat，紫色）：只要处于激活状态，它就会以每秒 20 次（每个游戏刻 1 次）的速度不断重复执行。

2. 条件与激活方式#

  • 条件制约 vs 无条件：
    • 无条件：不管前一个方块有没有执行成功，当前方块轮到了就照样跑。
    • 条件制约（方块箭头后方有个小缺口）：只有前一个方块“执行成功”了，当前方块才会触发。
  • 保持开启 vs 红石控制：
    • 保持开启：不需要红石线或拉杆，自己一直保持通电工作（常用于循环方块和连锁方块）。
    • 红石控制：必须旁边有红石信号（拉杆、按钮、红石火把）才会工作。
  • 执行延迟（Tick Delay）：
    • 可以在里面填数字。比如填 20，循环方块就会从“每刻执行”变成“每秒执行一次”（1秒 ≈ 20游戏刻）。

搭建时的注意事项与排错技巧#

  1. 看清箭头朝向：连锁方块必须被前一个方块的箭头“指着屁股”。如果箭头歪了，整条指令链就会在断开的地方停住。

第 2 章 找人与找位置——目标选择器与坐标用法#

怎样精准选中你想控制的目标？#

如果我们要给玩家发一把剑，输入 /give Steve iron_sword 很简单。但如果服务器里有很多人、名字各不相同，或者你想只挑血量最低的人、离你最近的怪物发奖惩，该怎么办？这就需要用到目标选择器和三维坐标。

选择器代号、过滤方括号与三大坐标系#

1. 常见目标选择器代号#

  • @a：所有玩家（包括死掉还没重生的）。
  • @p：离执行点最近的一名玩家。
  • @r：随机选一名玩家（加上参数也能随机选生物）。
  • @e：所有实体（玩家、小猪、僵尸、掉落物、盔甲架全算）。
  • @s：执行者自己（谁在运行指令就选谁）。

2. 方括号里的过滤条件（参数）#

在代号后面加上 []，可以在里面用逗号添加筛选条件：

条件类别例子说明
类型过滤type=cow, type=!player只选牛；加 ! 表示排除玩家
数量限制c=1, c=3只选最近的 1 个或前 3 个
圆形半径r=5, rm=2r=5 代表 5 格以内，rm=2 代表排除 2 格以内的
方块选区x=0,y=64,z=0,dx=5,dy=2,dz=5从 (0,64,0) 开始，圈出一个长宽高 5x2x5 的方盒子
标签筛选tag=vip, tag=!bad只选带有特定标签或没有该标签的实体
物品检测hasitem={item=apple,quantity=1..}检测背包里至少有 1 个苹果的人

3. 三大坐标体系#

  • 绝对坐标（固定位置）：例如 100 64 -20，地图上的固定点。
  • 相对坐标（~）：以自己为起点的偏移。~ ~2 ~ 代表自己头顶上方 2 格的位置。
  • 视线局部坐标（^）：以眼睛朝向为准，格式是 ^左/右 ^上/下 ^前/后。^ ^ ^3 代表自己视线正前方 3 格处。

第 3 章 指令的大脑——新版 /execute 上下文系统#

为什么旧版 execute 不够用了？#

以前的旧版 execute 语法是 /execute 玩家 坐标 指令，执行者和执行位置死死捆绑在一起，想做“让骷髅朝玩家看”、“把命令执行点转到眼睛处”或者“只有下雨天才执行”非常别扭。基岩版更新了全新的 /execute 语法，像搭积木流水线一样，让逻辑变得清晰且强大。

上下文流水线与常用积木块#

新版 execute 的基本格式是：

1. 改变身份与位置#

  • as <目标>：改变执行者是谁（把 @s 变成指定目标）。
  • at <目标>：把执行的位置、朝向和维度变成目标当时的状态。
  • positioned <x y z> 或 positioned as <目标>：只改坐标，不改朝向。
  • anchored (eyes|feet)：把基准点设置在眼睛或脚底。
  • facing <坐标> 或 facing entity <目标> (eyes|feet)：把执行朝向转为面朝指定地点或生物。
  • align xyz：把坐标的小数点全部向下取整，对齐方块正中心。

2. 条件判断积木#

  • if|unless entity <目标>：如果有 / 除非有某个实体才继续。
  • if|unless block <坐标> <方块名>：如果 / 除非某个位置是指定方块才继续。
  • if|unless score <目标> <计分项> matches <范围>：检测记分板分数是否满足条件。

常见小误区#

  1. as 与 at 没分清：
    • 写了 as @a，指令里的 @s 确实变成玩家了，但执行位置还在命令方块那里！
    • 如果想在玩家的位置执行，一定要写成 as @a at @s。
  2. 条件中断：如果前面的积木判定失败（比如 if block 没找到方块），整条指令后面所有的东西都会直接停掉，不会报错也不会执行 run。

第 4 章 逻辑判断技巧——用指令实现“或者”与复杂分支#

原生指令只能做“并且”，遇到“或者”怎么办？#

在游戏制作中，我们常遇到这种需求：“只要玩家有铁剑或者钻石剑，就可以进副本”；“只要队伍里有人没准备好，就不能开门”。原生的选择器中，多个条件都是默认同时满足的（“与”逻辑）。要实现“或者（OR）”、“除非同时满足（NAND）”这种分支，该怎么写？

常用逻辑对照速查#

  • 与逻辑（AND）：两个条件都要满足。

  • 非逻辑（NOT）：没有某个条件才执行。

  • 或逻辑（OR）：只要满足 A 或满足 B 其中一个就执行（反过来想：除非既没有 A 也没有 B，否则就执行）。

  • 异或逻辑（XOR）：A 和 B 只能满足其中恰好一个，全有或全无都不行。

2. 九种运算符号一览（operation）#

语法：/scoreboard players operation 接收者 计分项 符号 贡献者 计分项

运算符号作用简单示例与说明
+=加法A money += B money（把 B 的钱加到 A 身上）
-=减法A money -= B money（A 的钱减去 B 的钱）
*=乘法A money *= B money（A 的钱乘以 B 的钱）
/=整除A money /= B money（A 的钱除以 B，小数部分直接扔掉）
%=取模（求余数）A money %= B money（求 A 除以 B 后的余数，常做循环时钟）
=赋值A money = B money（把 B 的分数直接抄给 A）
<留较小者A money < B money（A 和 B 比，谁小就把谁存到 A）
>留较大者A money > B money（A 和 B 比，谁大就把谁存到 A）
><互相交换A money >< B money（A 和 B 的分数互换）

  • 10 分钟（12000 刻）：main_timer % 12000 == 0

数据计算小贴士#

  1. 整数除法会丢掉小数：在记分板里 5 / 2 的结果是 2，不是 2.5。如果你想算百分比，比如当前血量占总血量的百分比，一定要先乘 100 再除以最大血量！
  2. 通配符 * 的用法：* 会操作所有在这个记分项里留下过名字的人（包括退服玩家和假名字）。平时统计在线玩家时，建议优先使用 @a。

第 6 章 状态侦测技巧——检测潜行、睡觉、视线与天气#

怎么知道玩家在做什么动作？#

除了检测坐标和金币，游戏制作中常常需要探测玩家的行为：玩家现在是不是在偷偷潜行？是不是躺在床上睡觉？他现在眼睛正看着哪只怪物？天上是不是正在下雨？利用碰撞箱（Hitbox）高度差、视线回转三角算法和方块特性，我们不用任何外部插件也能精准识别。

姿态高度差与视线反射几何原理#

1. 姿态碰撞箱（Hitbox）高度分阶#

基岩版在 1.20.10 加入短潜行后，玩家在不同姿态下的碰撞箱高度是截然不同的：

  • 站立高度：约 1.8 格
  • 潜行高度：约 1.5 格
  • 爬行/游泳/滑翔高度：约 0.6 格
  • 睡觉高度：仅约 0.2 格

只要用 [y=~偏移, dy=0] 在头顶特定高度开一个小检测盒，就能一眼看出玩家处于什么姿态！

2. 视线检测（Look Detection）原理#

怎么知道玩家是不是正好看着某个目标？

  • 先从玩家眼睛出发，朝目标的方向往前走 1 格（facing 目标 ... positioned ^^^1）。
  • 然后转回玩家自己的朝向，往后倒退 1 格（rotated as @s ... positioned ^^^-1）。
  • 如果玩家正好看着目标，这一前一后就会回到原点；只要检测此时距离玩家自身是不是在 0.2 格以内（if entity @s[r=0.2]），就能精准判定玩家在看着它！

函数运行的规则限制#

  1. 单刻 10,000 条上限：在同一个游戏刻里，所有函数执行的总指令不能超过 10,000 条，否则会被系统强制切断。写循环递归时一定要留好退出条件。

Rawtext 结构与 Max 盔甲架展示方块（MBE）#

1. JSON 富文本（Rawtext）三大核心件#

用于 /tellraw、/titleraw：

  • text：直接写的文字，支持颜色代码（如 §a、§e）。
  • selector：动态显示某个目标的名字（如 {"selector": "@p"}）。
  • score：把记分板的分数动态镶嵌进文字里。

2. Max 盔甲架展示方块（MBE 技术）#

社区大神 Maxed_Out 发现了一个神奇的技巧：

  • 把盔甲架命名为 Grumm（让它倒立）。
  • 摆成特定的待机姿势，手上拿任意方块物品。
  • 用 /playanimation 播放僵尸手臂与恶魂缩放动画，就能把方块放大并精确对齐成一个真实的“自定义方块展示品”！

使用细节与防坑建议#

  1. 展示方块没有真实碰撞：用 MBE 做出的方块，玩家是可以直接穿过去的。如果你希望它像真方块一样能踩、能挡路，记得在它所在的位置放一个 barrier（隐形屏障方块）。
  2. 动画需要保持或重载：由于 /playanimation 是在玩家客户端渲染的，玩家离远再回来可能会恢复原状。可以在区域加载或玩家进服时重新触发一次。

第 9 章 算法优化与黑科技——二分法与 nx树 多重分流#

怎样用几条指令搞定成百上千次运算？#

如果你想做个批量出售箱：玩家可能有 1 个面包，也可能有 64 个面包。难道我们要写 64 条指令一条条测？如果想在玩家头顶用粒子瞬间画出一个完整的 3D 浑天球体，难道要写几百个命令方块？利用二分法和 nx树（MEF / execute fork），我们可以用最少的指令实现成百上千倍的效率爆发！

二分法思想与 nx树 分流裂变模型#

1. 二分法（二进制拆分）原理#

任何 1 到 64 之间的数字，都可以拆成 7 个 2 的次方数相加：

64, 32, 16, 8, 4, 2, 1

比如玩家有 50 个面包：50 = 32 + 16 + 2。
我们只要按从大到小的顺序检测这 7 档，仅需 7 步就能把任意数量的面包瞬间扣除并折算成金币，效率比传统的一格格扣高了几十倍！

2. nx树（MEF / execute fork）核心裂变原理#

在 /execute 指令中，如果你的选择器选到了 n 个目标，指令就会顺着这 n 个目标分裂成 n 条支线。
如果你把这种选择器串联 x 次，分支数量就会像一棵不断开叉的大树一样爆发式增长：

\text{生成实例数} = n^x

通过放置两只带有特定朝向的辅助船，利用 nx树（MEF）在单条指令中连续倍增旋转角度，单刻内就能生成数千个空间计算点！

避免卡服与死锁指南#

  1. nx树 必须限制数量（c=）：在写 nx树（MEF）时，每个嵌套选择器一定要加上 c=2 或类似的精确数量限制。如果直接写裸的 @e，周围一旦有几十只动物，嵌套几次就会产生几十万条分支，直接把服务器卡死。
  2. 辅助实体放进安全区：nx树（MEF）依赖的两只定位船要放在基岩保护房和常加载区里，防止被怪物打掉或者被水流冲走。
